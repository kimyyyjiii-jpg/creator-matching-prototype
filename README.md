# 크리에이터 매칭 추천 프로토타입

1인당 예산·카테고리·팔로워 규모를 입력하면, 예산 안에서 집행 가능한 크리에이터를 캠페인 목적에 맞춰 추천합니다.
기획은 [PRD.md](PRD.md), 로직 흐름은 [flowchart.md](flowchart.md)를 기준으로 구현했습니다.

**바로 보기**
- 데모 화면: https://kimyyyjiii-jpg.github.io/creator-matching-prototype/
- 로직 테스트: https://kimyyyjiii-jpg.github.io/creator-matching-prototype/tests/

## 실행

빌드나 패키지 설치가 필요 없습니다. 브라우저가 CSV를 `fetch`로 읽기 때문에 로컬 서버로 열어야 합니다. 프로젝트 루트에서 실행합니다.

```bash
python3 -m http.server 8000
```

- 앱: http://localhost:8000/
- 로직 테스트: http://localhost:8000/tests/ (PRD 수치·시나리오 자동 검증)
- 화면 테스트케이스: [TEST_CASES.md](TEST_CASES.md)

## 설계 근거와 트레이드오프

PRD의 핵심 판단을 요약했습니다. 자세한 근거와 데이터는 괄호 안 PRD 절에 있습니다.

| 판단 | 이유 | 감수한 점 |
|---|---|---|
| **필터와 점수 분리** (3.3) | 예산·카테고리·규모·플랫폼은 어기면 캠페인이 성립하지 않으므로 가중치가 아닌 필터로 둡니다. 점수는 "집행 가능한 후보 중 누가 더 나은가"만 판단합니다. | 조건을 조금만 벗어나도 결과에서 빠지므로, 0명·1~3명일 때 조건 넓히기 제안과 가까운 후보로 보완합니다. |
| **백분위 비교** (3.4) | 참여율·평균 조회수는 같은 팔로워 구간 안에서, 조회율은 같은 플랫폼 안에서 비교해 구간·플랫폼 간 구조적 차이를 걷어냅니다. | 200명 안의 상대값이라 데이터가 바뀌면 같은 크리에이터의 점수도 바뀝니다. |
| **보정 평점** (3.4) | 집행 건수가 적은 평점을 전체 평균 쪽으로 당깁니다(집행 1건 4.9점 → 4.50). 표본이 적은 만점을 그대로 믿지 않기 위해서입니다. | 실제로 잘하는 신규·소수 집행 크리에이터가 평점에서 손해를 봅니다. |
| **신규 단가** (3.2) | 이력이 없어 단가가 0원인 27명은 같은 규모 최저 단가로 예산을 판정해 결과에 들어올 기회를 넓히고, 화면에는 비슷한 크리에이터 2명 평균을 추천 단가로 보여줍니다. | 실제 견적이 예산을 넘을 수 있습니다. 추천 단가도 이 데이터에서는 실제 단가와 평균 43% 차이 나는 참고값이라 "협의 필요"를 함께 표시합니다. |
| **목적 프리셋** (3.5) | 가중치를 10점 안팎으로 옮기면 순위가 거의 바뀌지 않아(순위 상관 0.98), 미세 조정 슬라이더 대신 목적별 프리셋 4개를 택했습니다. | 광고주가 원하는 비율을 직접 정할 수는 없습니다. |
| **예산적합도** (3.4, 3.5) | 종합 추천에서 1인당 예산에 맞는 급을 우대합니다. 예산을 필터로만 쓰면 예산의 1/4 수준 후보가 1위가 되는 문제가 있었습니다. 기준 금액은 입력 예산이 아니라 후보 중 최고 단가입니다. | 유독 비싼 1명이 기준 금액을 끌어올리면 나머지가 감점될 수 있습니다. 가중치 20과 구간 경계(0.7/0.4)는 실제 성과로 검증하지 않은 판단값입니다. |

```

  data/csv.js               CSV 파서 (BOM·따옴표 처리)
  data/dataset.js           정제, 신규 단가 범위·추천 단가, 보정 평점, 지표·백분위, 태그·배지 판정 (로딩 시 1회)
  data/load.js              CSV 로드
  logic/constants.js        구간, 가중치, 태그 기준 등 PRD 상수
  logic/percentile.js       평균 순위 백분위
  logic/recommend.js        예산 검증, 필터, 예산적합도, 점수, 태그, 기여 지표, 정렬, 태그 필터
  logic/relax.js            조건 넓히기 제안(0명·1~3명 공통), 가까운 후보

```

## 구현 메모

- 백분위는 `(값이 더 작은 개수 + 같은 값 개수 × 0.5) ÷ 모집단 수`로 계산합니다. 모집단은 200명 전체를 구간(조회율은 플랫폼)별로 나눈 집단이고, 비용 지표만 이력 없는 크리에이터를 뺍니다.
- 매칭 점수로 추천순을 정하고, 숫자는 카드 상세에만 보여줍니다. 종합 추천의 예산적합도는 추천할 때마다 현재 후보군으로 계산합니다.
- 신규(집행 이력 없음) 크리에이터는 예산 판정에 같은 규모 최저 단가를 쓰고, 화면에는 비슷한 크리에이터 2명 평균인 추천 단가를 참고로 보여줍니다.
- 현재 데이터에는 없지만, 숫자 필드 결측·음수·형식 오류는 해당 지표만 중립값 0.5로 처리하고, ID·채널명이 없는 행은 제외합니다. 팔로워 수를 읽을 수 없는 크리에이터는 구간을 정할 수 없어 어떤 규모 조건에도 걸리지 않습니다.
